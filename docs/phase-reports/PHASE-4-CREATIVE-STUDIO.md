# Phase 4 – Creative Studio (AI images and videos)

Status: implemented and tested with **test-only providers**. **No real image or video was generated by a real provider**: no API key was available. The OpenAI adapters are written against the documented APIs and verified only with stubbed HTTP responses.

## 1. Implemented modules
- `packages/shared/src/creative.ts`: vocabularies (image types, styles, backgrounds, themes, aspect ratios, resolutions, platforms, video formats and styles, brand roles, limits).
- `packages/creative` (`@touma/creative`): provider contracts (`ImageProvider`, `VideoProvider`), OpenAI image adapter (`gpt-image-1`, generations and edits with input fidelity) and video adapter (submit / status / content), error classification with key redaction, prompt builders, image composition (product cutout, exact compositing, overlay text, logo placement), cost estimation, test-only fakes.
- `apps/api/src/creative`: brand kit, creative service (images, videos, variations, history, favorites, delete), quota service (atomic), BullMQ worker (`touma.creative`), controller, queue and provider wiring.
- `apps/api/src/media`: `ingestGenerated`, `readOriginal`, `removeGenerated`, `?download=1`.
- `apps/api/src/ai` and `packages/ai-engine`: `STORYBOARD` task and agent, storyboard validation, brand kit passed to content generation (`content-creator@2`).
- `apps/web`: six dashboard pages and components, EN/FR translations, storyboard view in AI history.

## 2. Database migration
`20261111084926_creative_studio`: enums `CreativeKind`, `CreativeStatus`, `AITask.STORYBOARD`; tables `BrandKit`, `CreativeGeneration`, `CreativeOutput`; image/video counters on `AIUsagePeriod`. Applied to the dev and test databases; `prisma migrate status` reports no drift.

## 7. Remaining limitations (honest list)
1. **Real provider generation is untested.** The OpenAI image and video adapters have never called the real APIs. Verify with a real key before announcing (procedure in CREATIVE.md). The video endpoint shape in particular follows documentation and may need adjustment.
2. **Video is a single provider clip** up to the provider's maximum length; no stitching or editing (no ffmpeg). Video thumbnails exist only if the provider returns a poster.
3. **EXACT mode needs a clean photo** (plain or transparent background). Busy backgrounds fail with `PRODUCT_CUTOUT_FAILED`; the user can switch to GUIDED, where preservation is best effort and flagged.
4. **Overlay fonts** depend on fonts installed on the worker. The API image now installs fontconfig and common fonts, but **that Docker change was not built here** (Docker daemon unavailable). Custom brand fonts not installed fall back to a default.
5. **HD** may be upscaled from the provider's native size and is flagged.
6. **Cost figures are estimates** from `CREATIVE_MODEL_PRICING`; without it cost is unknown, not zero. Not a bill.
7. **Overlay grounding is rule-based:** it checks prices, phones, URLs and emails against verified data, not every claim in free text.
8. **Polling, not push**, and no cancel for a queued job. No scheduled generation or batch campaigns.
9. **Billing is not connected:** plan limits (`aiImagesPerMonth`, `aiVideoSecondsPerMonth`) are read when a subscription exists; subscriptions arrive in Phase 10.
10. **No independent security review** of the new code; checks are the automated tests above. The new CI steps and Docker images have still not run on GitHub.
11. Browser tests use deterministic fake providers, so they check the product workflow, not image or video quality.

Phase 5 has not been started.
